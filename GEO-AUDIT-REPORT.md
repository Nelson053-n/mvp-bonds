## Executive Summary

**Overall GEO Score: 66/100 (Fair)**

У Bond AI **выдающийся технический и контентный фундамент** для цитируемости AI-системами: чистый server-side рендеринг, явный allow всех AI-краулеров в robots.txt, наличие `llms.txt`, два sitemap, богатая schema.org-разметка (FinancialProduct, FAQPage, Article, Organization, SoftwareApplication) и Q&A-структура на каждой публичной странице. По техническому GEO и schema сайт уже в топ-эшелоне.

Единственный, но решающий разрыв — **Brand Authority и Platform Optimization**: вне собственного домена бренд практически не существует. Веб-поиск «Bond AI / bondai.ru» возвращает только сам сайт — ноль упоминаний на Reddit, Wikipedia, в обзорах, на профильных площадках. `Organization.sameAs` пуст. AI-модели опираются на третьесторонние сигналы для распознавания сущности и доверия — без них даже идеально размеченный сайт реже попадёт в ответ как рекомендуемый бренд. Вторичный разрыв — E-E-A-T: контент глубокий и точный, но автор везде указан как организация, без именованного эксперта с квалификацией.

## High Priority Issues (Fix Within 1 Week)

### H-1. Бренд не распознаётся как сущность вне своего домена
- **Категория:** Brand Authority / Platform Optimization
- **Свидетельство:** веб-поиск по «bondai.ru / Bond AI облигации» возвращает только сам сайт; конкуренты (Cbonds, Finam AI-скринер, dohod.ru, Aigenis) присутствуют, Bond AI — нет. Нет упоминаний на Reddit, Wikipedia, vc.ru, Habr, профильных форумах (smart-lab, banki.ru).
- **Почему важно для GEO:** LLM формируют «знание о бренде» из третьесторонних источников, на которых обучались/которые цитируют. При нулевом внешнем следе сервис не попадёт в ответ на запрос «какой сервис для портфеля облигаций посоветуешь».
- **Фикс:** см. план ниже (vc.ru/Habr-публикации, ответы на smart-lab/Reddit r/specialed→r/investing-аналоги, заявка в каталоги, Telegram-канал). Это самый высокий ROI для GEO прямо сейчас.

### H-2. `Organization.sameAs` пуст
- **Категория:** Schema / Brand Authority
- **Локация:** `app/ui/landing.html:1244` → `"sameAs": []`
- **Почему важно:** `sameAs` — прямой машиночитаемый мост от сайта к профилям бренда (Telegram-канал, VK, YouTube, GitHub). Это первый сигнал, по которому краулер связывает домен с сущностью.
- **Фикс:** как только появятся внешние профили (H-1) — заполнить массив их URL. До этого создать хотя бы Telegram-канал/VK-страницу и вписать их.

### H-3. Нет именованного автора/эксперта (E-E-A-T)
- **Категория:** Content E-E-A-T
- **Локация:** `app/ui/uchebnik.html:38` — `"author": {"@type": "Organization", "name": "Bond AI"}`
- **Почему важно:** для финансового (YMYL) контента AI-системы и поисковики сильно взвешивают экспертность автора-человека с квалификацией. Учебник по облигациям — классический YMYL.
- **Фикс:** добавить `Person`-автора с краткой биографией и областью экспертизы (например, «частный инвестор / разработчик, N лет на рынке облигаций»), блок «Об авторе» внизу `/uchebnik`, и сослаться на него в `Article.author`. Даже один реальный человек с указанной экспертизой кратно усиливает сигнал.

## Medium Priority Issues (Fix Within 1 Month)

### M-1. Нет `aggregateRating` / отзывов
- Осознанно пропущено (нет реальных данных — корректное решение, не выдумывать). Но это упущенный citability-сигнал. **Фикс:** когда появятся реальные пользователи/отзывы (Telegram, форма) — добавить честный `AggregateRating` к `Organization`/`SoftwareApplication`.

### M-2. Учебник — единственная длинная статья; нет тематического кластера
- `/uchebnik` плотный и качественный (24 определения в глоссарии, 6 FAQ, схемы), но это одна страница. **Фикс:** разнести в кластер отдельных статей-ответов под конкретные запросы («Как считается НКД», «ОФЗ vs корпоративные облигации», «Что такое оферта по облигации», «Флоатеры: когда брать»). Каждая = отдельный indexable URL с Article+FAQPage → больше точек цитирования.

### M-3. `Person`-сущности нет в графе организации
- Нет связки Organization → founder/employee. **Фикс:** при появлении автора (H-3) связать через `founder`/`author`, добавить `Person.sameAs` на его публичные профили.

### M-4. Нет видимой даты обновления данных на bond-страницах в schema
- Текст содержит «данные MOEX на 16 июня 2026» (отлично для свежести в глазах краулера), но это не вынесено в `dateModified`. **Фикс:** добавить `dateModified` в JSON-LD bond-страниц — усиливает сигнал свежести, критичный для финданных.

## Category Deep Dives

### AI Citability (88/100)
**Сильно.** Каждая публичная страница — server-rendered с осмысленным, извлекаемым контентом:
- **Bond-страницы** — образец citability: H1 с тикером и сутью («ОФЗ 33 CNY (RU000A10DQA8): цена, доходность и купоны»), title с конкретными числами («доходность 6,99%, купоны и погашение»), meta description с фактами, вводные абзацы прозой («"ОФЗ 33 CNY" — ОФЗ, торгуется на Московской бирже под тикером…»), секции «Обзор / Параметры / Вопросы и ответы / Похожие облигации». AI легко выдернет точную цитату с цифрой.
- **Учебник** — 24 термина в формате определение→объяснение (идеальный extractable-формат), 6 FAQ.
- **Landing** — 8 FAQ в FAQPage-schema, тематические H2 («Как AI подбирает портфель», «Тарифы — бесплатно навсегда»).

**Что докрутить:** вынести в кластер статей (M-2); часть ответов сделать ещё короче/самодостаточнее (чтобы цитировались без контекста).

### Brand Authority (25/100)
**Главная слабость.** Внешний след отсутствует. Поиск возвращает только собственный домен; `sameAs: []`. Нет Wikipedia, Reddit/форумов, обзоров, упоминаний в СМИ/блогах. Для AI-рекомендации это решающий фактор — модель должна «знать» бренд из независимых источников. Конкуренты в этой нише уже занимают место в выдаче.

### Content E-E-A-T (62/100)
**Хорошо по содержанию, слабо по авторству.** Плюсы: глубокий точный контент (YTM, НКД, оферта, ВДО, флоатеры, рейтинги АКРА/Эксперт РА, налоги/ИИС), явные контакты (`support@bondai.ru`), прозрачность безопасности (bcrypt/JWT, ФЗ-152, «не храним банковские данные», токен Т-Банка только на чтение), дисклеймер «не ИИР». Минусы: автор = организация, нет человека-эксперта с квалификацией, нет страницы «Об авторе/команде», `datePublished=dateModified=2026-06-08` (нет истории обновлений).

### Technical GEO (95/100)
**Эталонно.** 
- `robots.txt` явно `Allow: /` для GPTBot, OAI-SearchBot, ChatGPT-User, ClaudeBot, PerplexityBot, Google-Extended, Applebot-Extended; приватные зоны (`/app`, `/auth`, `/portfolios`, `/admin`…) закрыты — ровно как надо.
- `llms.txt` присутствует и содержателен (описание продукта, карта ключевых страниц, возможности, контакт).
- Два sitemap (`sitemap.xml` + `sitemap-bonds.xml` 185 KB со всеми бумагами).
- Полный SSR — весь контент в HTML без JS-зависимости.
- Security: HSTS, CSP, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`.
- Перф: inline-критический CSS, без render-blocking внешних JS на landing, публичный edge-кэш (`max-age=300, stale-while-revalidate=86400`).

### Schema & Structured Data (92/100)
**Очень сильно.** Покрытие по типам:
- Landing: `Organization`, `WebSite`, `SoftwareApplication`, `FAQPage`(8), `Offer`, `Audience`, `ContactPoint`, `ImageObject`.
- Bond-страница: `FinancialProduct`, `FAQPage`, `BreadcrumbList` — редкое и ценное сочетание для финтеха.
- Каталог `/bond`, `/calc`: `CollectionPage` + `BreadcrumbList` + `FAQPage`.
- Учебник: `Article` + `FAQPage` + `WebPage` + `Organization`.

**Минусы:** `sameAs` пуст, нет `aggregateRating`, автор не `Person`, нет `dateModified` на bond-страницах.

### Platform Optimization (35/100)
Присутствие — только собственный сайт. Нет YouTube, Reddit/форумов, Wikipedia, профилей в каталогах, активного соц-канала. Telegram-бот поиска облигаций готов в коде, но публично не анонсирован. Это и площадки, на которых обучаются/которые цитируют AI-модели — пустота здесь напрямую снижает шанс рекомендации.
